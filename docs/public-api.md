# Public API

This document is normative for the implemented RAGLight 4 API. Planned APIs
are listed separately and must not be presented as available.

## Root facade

The package root exports exactly two names:

```python
from raglight import PipelineConfig, RAGPipeline
```

`RAGPipeline` coordinates classic retrieval, optional reranking, and
generation. Components are keyword-only constructor arguments. The pipeline is
stateless: callers pass history explicitly to `generate` or `stream`, or create
an isolated session.

```python
pipeline = RAGPipeline(
    llm=my_llm,
    embeddings=my_embeddings,
    vector_store=my_vector_store,
    reranker=my_reranker,  # optional
    config=PipelineConfig(top_k=5),  # optional
)

response = pipeline.generate("What is RAGLight?", history=[])
answer: str = response.answer
chunks = pipeline.stream("What is RAGLight?", history=[])
```

`PipelineConfig` is immutable. It owns `top_k`, which must be greater than zero,
and optional serializable component selections used by registry-backed
construction.

## Conversation sessions

```python
from raglight.pipeline import ConversationSession

session: ConversationSession = pipeline.create_session(
    session_id="user-123",  # optional; a UUID is generated by default
    history=[{"role": "user", "content": "An earlier message"}],
)

response = session.generate("Continue the conversation")
chunks = session.stream("Stream the next answer")
history = session.history
session.clear()
```

`ConversationSession` owns conversation history; `RAGPipeline` never does.
Multiple sessions can safely reuse one pipeline without sharing messages. A
session copies initial history, and its `history` property returns detached
snapshots so callers cannot mutate committed state indirectly.

`generate()` commits the user and assistant messages only after the pipeline
returns successfully. `stream()` commits the concatenated assistant answer only
after the stream is fully consumed. If generation fails, streaming fails, or a
stream is closed early, that turn is not committed. Operations within one
session are serialized; separate sessions do not share a session lock.

## Directory ingestion

`RAGPipeline.ingest(...)` is the single public ingestion workflow. The
pipeline discovers files and coordinates parsing and persistence; document
processors and vector stores retain their provider-independent boundaries.

```python
from raglight import RAGPipeline
from raglight.integrations import default_registries
from raglight.models import FolderSource

pipeline = RAGPipeline(
    llm=my_llm,
    embeddings=my_embeddings,
    vector_store=my_vector_store,
    document_processors=default_registries.document_processors,
)

result = pipeline.ingest(
    [
        FolderSource(
            path="./knowledge",
            recursive=True,
            ignored_directories=(".git", ".venv", "private"),
            chunk_size=2500,
            chunk_overlap=250,
        )
    ]
)
```

`FolderSource` rejects invalid chunk settings. `ingest()` rejects missing and
non-directory paths before processing them. Traversal order is deterministic;
symlinks are not followed; unsupported extensions are explicit skips. Built-in
processor entries cover text, Markdown, HTML, PDF, and supported source-code
extensions. Register an extension to add or replace processing behavior:

```python
default_registries.document_processors.register(
    "rst",
    MyRstProcessor,
    replace=True,
)
```

`IngestionResult` reports `discovered_count`, successful `processed_count`,
indexed document-chunk `indexed_count`, `skipped_count`, and `failed_count`.
`skipped` contains paths and reasons; `failures` contains paths, stages, and
safe error messages. Processing and indexing failures are isolated per file.
`to_dict()` produces a transport-friendly value for future delivery layers.

The configured vector store must implement `IngestionVectorStore`, which adds
`add_documents(documents)` to the retrieval contract. `from_config(...)`
automatically uses the supplied registries for ingestion. Direct construction
must pass a document-processor registry explicitly so importing the core never
loads optional parsing packages.

## Domain models

```python
from raglight.models import (
    ComponentConfig,
    Document,
    ExecutionEvent,
    ExecutionStatus,
    FolderSource,
    IngestionFailure,
    IngestionResult,
    IngestionSkip,
    RAGResponse,
)
```

`Document(page_content: str, metadata: dict[str, object] = {})` is the value
exchanged by retrieval, reranking, and document-processing boundaries.
`ComponentConfig(name, options)` is the provider-independent serialized form
of one named integration.

### Structured generation results

`RAGPipeline.generate(...)` returns an immutable `RAGResponse` containing:

- `answer`: the generated text;
- `sources`: the final documents supplied to generation, after optional
  reranking;
- `events`: completed `retrieval`, optional `reranking`, and `generation`
  stages;
- `timings`: non-negative stage durations in milliseconds plus `total`;
- `metadata`: pipeline-level facts such as `top_k`, retrieved document count,
  and whether reranking ran;
- `trace_id`: a unique identifier for correlating one execution.

Each `ExecutionEvent` has a `stage`, `status`, `duration_ms`, optional message,
metrics, and metadata. Event statuses are `started`, `completed`, or `failed`;
the synchronous classic pipeline emits completed events for stages represented
in a successful response.

`RAGResponse.to_dict()` and `ExecutionEvent.to_dict()` provide
transport-friendly dictionaries for future delivery layers. Raw logs are not
part of the response contract. `stream(...)` continues to yield text chunks;
the delivery-level streaming event protocol is designed separately.

## Extension contracts

```python
from raglight.contracts import (
    DocumentProcessor,
    EmbeddingModel,
    IngestionVectorStore,
    LLM,
    Reranker,
    VectorStore,
)
```

These are runtime-checkable structural protocols. Implementations do not
inherit from a RAGLight base class and need no registration.

| Contract | Required methods |
| --- | --- |
| `LLM` | `generate(input)`, `generate_streaming(input)` |
| `EmbeddingModel` | `embed_documents(texts)`, `embed_query(text)` |
| `VectorStore` | `similarity_search(question, k=5)` |
| `IngestionVectorStore` | `similarity_search(question, k=5)`, `add_documents(documents)` |
| `Reranker` | `rerank(question, documents, top_k)` |
| `DocumentProcessor` | `process(file_path, chunk_size, chunk_overlap)` |

The LLM input contains `question` and `history`. Vector stores and rerankers
exchange `Document` values. A processor returns a dictionary with `chunks` and
`classes` document lists.

## Built-in integrations

Concrete providers are public only from explicit provider modules:

```python
from raglight.integrations.openai import OpenAIEmbeddings, OpenAILLM
from raglight.integrations.qdrant import QdrantVectorStore
```

Provider modules may require their matching optional extra. Importing the root,
contracts, or models must not load those dependencies. Undocumented deep paths
inside `raglight.integrations` are implementation details.

### Integration registries

The registry API is public from the integration namespace:

```python
from raglight.integrations import (
    IntegrationRegistries,
    IntegrationRegistry,
    default_registries,
)
```

Built-in entries are lazy import references. Inspecting registry names does not
load an integration module or SDK. A registry normalizes names, rejects
accidental duplicate registration, and reports available names for failed
lookups.

Custom components can optionally participate in named configuration:

```python
default_registries.llms.register("my-llm", MyLLM)
```

Direct injection does not require registration.

### Serializable construction

`PipelineConfig.from_dict(...)` validates an in-memory mapping.
`PipelineConfig.from_file(...)` supports `.json` and `.toml` files. Named
construction requires explicit registries so the pipeline never imports a
concrete provider:

```python
from raglight import PipelineConfig, RAGPipeline
from raglight.integrations import default_registries

config = PipelineConfig.from_file("raglight.toml")
pipeline = RAGPipeline.from_config(config, registries=default_registries)
```

The required component sections are `llm`, `embeddings`, and `vector_store`;
`reranker` is optional. Each section contains `name` and an optional `options`
mapping. The configured embedding instance is injected into the vector-store
factory as `embeddings_model` and cannot be overridden by serialized data.

## Stability rules

- A documented implemented name is public.
- Root exports are deliberate and tested.
- Public inputs and outputs have type annotations.
- Provider SDK types do not cross core boundaries.
- Adding a provider does not modify `RAGPipeline`.
- Incompatible public behavior requires a major release.
- Every public workflow has offline automated coverage.

The v3 `Builder`, `RAG`, global `Settings`, provider ABCs, agentic runtime,
server, CLI, and UI are removed and are not v4 aliases or compatibility shims.

## Planned capabilities

The following are not implemented:

- a separately designed agentic API;
- delivery applications built on the v4 core.

Agentic execution will remain distinct from classic `RAGPipeline`: it will not
use inheritance or an `agentic=True` flag. See
[`architecture.md`](architecture.md) and
[`migration-v3-to-v4.md`](migration-v3-to-v4.md).
